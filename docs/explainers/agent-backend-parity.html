Subject
Claude Code 与 Open Code 后端在 Comate 中的功能差异与缺失清单

结论先行：Open Code 在 Comate 里不是“半成品”，而是覆盖了普通 GUI 会话的核心路径；真正的缺口集中在机器人入口、分析统计、定时任务完成判定、以及 Comate 的 MCP/Skill/Plugin 生态。下面按源码给出的“能力声明表”逐条拆解。

1. 权威来源：能力声明表

项目里唯一的事实来源是 src/server/services/agent-backends.ts 中的 CAPABILITY_TABLE。Claude 是 canonical 后端，默认全部 full；Open Code 必须逐项声明，未声明即 unavailable。

2. 完整缺口清单（Open Code 相对 Claude 缺少或降级）

2.1 Bot 会话 —— 强制锁死 Claude

这是清单里最大的一块。ChatService.resolveSessionBackend 对任何 isBotSession 都直接返回 'claude'，完全无视应用默认后端： 

// src/server/services/chat-service.ts:994-1002
private async resolveSessionBackend(
  session: ChatSession,
  isBotSession?: boolean,
): Promise<BackendId> {
  if (session.backend) {
    return session.backend as BackendId;
  }
  return isBotSession ? 'claude' : (await resolveDefaultBackend()).backend;
}

影响范围：WeCom 机器人、飞书机器人、所有通过 botEventHandler 进入的会话。文档也明确写了这是 R14 “out of scope for v1”。

来源：src/server/services/chat-service.ts:991-992；docs/acceptance/agent-backend-parity-checklist.md “Known declarations to revisit”

2.2 Analytics —— Open Code 会话不计入用量统计

能力表里 analytics 对 Open Code 是 unavailable。transcript/usage 在 Open Code 路径里虽然能拿到 token 数，但未被纳入 Comate 的用量分析 UI。

来源：src/server/services/agent-backends.ts:93-97；docs/acceptance/agent-backend-parity-checklist.md:19

2.3 定时任务 —— 可运行，但缺少完成判定器

定时任务触发时会新建会话，Claude 后端会注入 Stop hook，持续追问直到模型写出 GOAL_STATUS: COMPLETE 或达到轮次上限。Open Code 只能拿到包装后的 prompt，没有等价判定器。 

// src/server/services/chat-service.ts:1127-1135
if (session.source === 'scheduled' && backend === 'claude') {
  options.hooks = {
    ...options.hooks,
    Stop: [...(options.hooks?.Stop ?? []), { hooks: [makeScheduledRunStopHook(session.id)] }],
  };
}

因此在 SchedulerService.finishRun 里，Open Code 不会因为没有 GOAL_COMPLETE_MARKER 而被判失败，但这也意味着它无法主动确认任务真的“完成”了目标。

来源：src/server/services/chat-service.ts:1127-1135；src/server/services/scheduler-service.ts:453-470

2.4 MCP 生态 —— 只有浏览器 MCP 被接入

buildSdkOptions 为 Claude 后端拼装了一整组 MCP 服务器：

  • 用户在 Workspace 里配置的 MCP servers（workspace.mcpServers）
  • Plugin 声明的 MCP servers（loadPluginMcpServers）
  • Comate 内置的浏览器 MCP
  • Comate 内置的定时任务 MCP

但 Open Code 的 serve config 只显式注入了浏览器 MCP： 

// src/server/services/opencode-adapter.ts:100-109
function buildSessionMcpConfig(comateSessionId: string, taskToken: string): Record<string, unknown> {
  return {
    [BROWSER_MCP_SERVER_KEY]: {
      type: 'remote',
      url: `${getSidecarBaseUrl()}/mcp/browser/${comateSessionId}`,
      headers: { Authorization: `Bearer ${taskToken}` },
      oauth: false,
    },
  };
}

也就是说，Open Code 会话看不到用户 MCP、Plugin MCP 和定时任务 MCP。这是把“plugins / skills / 定时任务”变成缺口的真正技术原因。

来源：src/server/services/chat-service.ts:1732-1782；src/server/services/opencode-adapter.ts:81-109

2.5 Skills / Plugins 的 Slash 命令 —— 仅 Open Code 原生命令可用

Comate 的 /commands 路由是后端感知的：Claude 路径走 commandsService，合并 SDK 命令、.claude/commands、.claude/skills、个人命令和 Plugin 命令；Open Code 路径则只向该会话的 opencode serve 取 /command： 

// src/server/routes/workspace-commands.ts:23-33
if (sessionId) {
  const session = workspaceStore.getLocalSession(sessionId);
  if (session?.backend === 'opencode') {
    const commands = await chatService.getSessionBackendCommands(sessionId);
    res.json({ commands, partial: false });
    return;
  }
}

因此 Open Code 能执行的是 opencode 自己 advertise 出来的命令，而 Comate 安装的 Skill/Plugin 提供的 slash 命令不会出现在列表里，也不会被 executeBackendCommand 执行。

来源：src/server/routes/workspace-commands.ts:20-33；src/server/services/chat-service.ts:668-688

2.6 Session 生命周期 —— Open Code 有几个未对齐的边角

这些不是“功能缺失”，而是当前实现默认走 Claude SDK，Open Code 会话会报错或行为不完整：

  • Fork：forkSession 始终调用 sdkClient.forkSession，不会 fork opencode 远程会话。
  • Rename：非 draft 会话的改名直接调用 sdkClient.renameSession，对 Open Code 会话无效。
  • Delete：只删本地 SQLite 行，没有清理 opencode 后端会话。
  • List：扫描所有 workspace 的 SDK 会话时不会发现 opencode 会话。
  • Background stop：Open Code query handle 的 stopTask 是 no-op。

来源：src/server/services/chat-service.ts:472-474, 512-533, 535-543；src/server/services/opencode-adapter.ts:184-188

2.7 Session 设置 —— fastMode / 系统提示预设

  • Fast mode：Claude 会读 session.fastMode 和 provider.supportsFastMode，Open Code 的 buildServeConfig 没有传这个标志。
  • System prompt preset：Claude 支持字符串或 preset 对象；Open Code 只转发字符串，对象形式会被丢弃。

来源：src/server/services/chat-service.ts:1793-1794；src/server/services/opencode-adapter.ts:526-533

2.8 Hooks —— 两个后端都没有

Workspace settings 里可以配置 hook 脚本，但能力表明确声明 hooks: unavailable 在 Claude 和 Open Code 上都是 unavailable。执行端目前没有任何消费者。

来源：src/server/services/agent-backends.ts:77,105

3. 你提到的 “message” 指什么？

如果指普通聊天消息（发送、流式接收、消息归一化、渲染），那是 full parity。message-normalizer.ts 是后端无关的，opencode-event-mapper.ts 已经把 opencode 的 SSE 事件翻译成 SDKMessage 形状。

如果指Bot 消息入口（WeCom/飞书来的消息），那它属于 2.1 的缺口：所有 Bot 会话都被锁在 Claude 后端。

来源：src/server/services/opencode-event-mapper.ts；src/server/services/message-normalizer.ts

4. 一句话总结

Open Code 已覆盖“人在 Comate GUI 里正常聊天、审批、工具调用、浏览器、子代理、换模型”的完整路径；缺口集中在企业/自动化入口（Bot、Analytics、定时任务完成判定）、Comate 扩展生态（MCP、Skill、Plugin），以及若干 Session 生命周期操作（fork/rename/delete/stopTask）。Bot 会话被强制绑定 Claude 是最显性的限制。
