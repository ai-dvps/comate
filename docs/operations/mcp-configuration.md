# MCP 配置管理

在「设置 → MCP」中管理第三方服务。Claude、Codex、OpenCode 的桌面会话使用同一套服务配置与授权。

## 添加与测试

1. 选择「全局」或一个工作区。没有打开工作区时，也可以管理全局服务。
2. 点击「添加服务」，选择本地 stdio、远程 HTTP 或 SSE。
3. 本地服务填写可执行程序、启动参数与环境变量。每个参数占一行，参数里的空格会完整保留。程序不会通过 shell 拼接执行，工作目录取会话的工作区目录。
4. 远程服务填写地址与所需请求头。不需要认证的服务可不填请求头。HTTP 使用 Streamable HTTP，旧服务可以显式选择 SSE。
5. 保存后点击「测试连接并查看工具」。测试执行 MCP 握手与工具发现，不调用业务工具。

也可以导入常见的 `mcpServers` JSON：

```json
{
  "mcpServers": {
    "local-example": {
      "command": "node",
      "args": ["/absolute/path/server.js", "an argument with spaces"],
      "env": { "EXAMPLE_TOKEN": "replace-with-your-token" }
    },
    "remote-example": {
      "type": "http",
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer replace-with-your-token" }
    }
  }
}
```

JSON 中未写 `type` 时，有 `command` 的条目视为 stdio，其他条目视为 HTTP。重复名称、未知字段或无效字段会使整次导入失败；已保存的服务保持原值。导入不会覆盖同一范围中的已有名称，修改已有服务请使用「编辑服务」。

## 范围与继承

| 操作 | 结果 |
| --- | --- |
| 添加全局服务 | 所有未覆盖该名称的工作区都可使用 |
| 在工作区添加同名服务 | 完整覆盖全局条目，连接参数和凭据均独立 |
| 仅在此工作区禁用 | 创建工作区禁用记录，全局服务仍供其他工作区使用 |
| 删除工作区条目 | 恢复继承当前同名全局服务；全局服务不存在时不再生效 |
| 删除工作区 | 删除该工作区的 MCP 配置和独立授权，全局配置保留 |

显式配置和工作区禁用记录优先于同名插件服务。内置浏览器与定时任务工具保持各自入口。机器人和定时执行会话沿用原来的配置路径，不继承新增的全局 MCP 或 OAuth 授权。

## OAuth 与凭据

远程服务勾选 OAuth 后，保存并点击「登录 / 重新授权」。Comate 打开系统浏览器，通过临时的本机回调接收授权结果。可以取消登录；未完成的操作在 10 分钟后过期。失败或取消后可重新发起。

支持标准服务发现、PKCE、预注册客户端、客户端元数据 URL 与动态客户端注册。若服务不提供注册能力，请填写服务方提供的 Client ID。授权服务需要 HTTPS，本机测试服务可使用 HTTP。需要额外权限范围时，可在连接配置中填写 scopes。

全局条目的授权由继承它的工作区共享，工作区覆盖单独授权。过期凭据有 refresh token 时由 Comate 协调刷新；无法刷新则显示需要重新授权。取消、替换配置和再次登录后，旧回调或旧刷新结果不会覆盖新的授权。

保存的连接与 OAuth 材料使用现有凭据加密机制持久化。列表只显示安全地址、参数数量和凭据字段名。常规编辑名称或启用状态会保留原连接；只有勾选「替换连接配置」才会整体重填连接、清除旧凭据与授权。秘密草稿不写入浏览器持久存储。

## 已有会话的更新

配置保存后，新会话直接使用当前配置。已有桌面会话只暂停受影响服务的新调用，等待已经派发的调用结束，再交换连接并确认后端读取了新工具清单。它不等待整个聊天任务结束，也不会为配置更新强行终止正在执行的调用。

Claude 与 OpenCode 直接取得各服务的工具定义。仓库锁定的 Codex 运行时会缓存工具定义，因此使用稳定的 `discover` / `invoke` 入口：先读取当前工具 ID 与输入格式，再调用对应工具。Comate 的审批仍显示原始服务和工具，服务变更无需重建聊天会话。应用验证会通过真实 MCP 调用重新读取当前目录，不把普通状态接口或 reload 成功当作更新完成。

「已保存」与「已应用」分别显示。若某会话应用失败，该服务在该会话中保持不可用，无关服务继续工作。排查连接、程序路径或授权后点击「重试应用」。重试不会重放已完成的业务调用。

| 状态 | 处理方式 |
| --- | --- |
| 程序未找到 | 检查可执行文件路径及 PATH，参数按独立项填写 |
| 连接失败 | 检查地址、网络、传输方式及请求头，再测试连接 |
| 需要授权／重新登录 | 发起 OAuth，或整体替换连接中的手动凭据 |
| 凭据无法解密 | 恢复原加密密钥，或重新填写完整连接；也可以删除条目 |
| 等待正在执行的调用完成 | 等待该调用正常返回，或通过会话的常规取消操作结束它 |
| 会话应用失败 | 保存已成功；排查服务后重试该会话的应用操作 |
| 修订冲突 | 刷新列表并重新打开编辑，不会自动覆盖另一个窗口的修改 |

旧工作区的 MCP 名称、命令及参数在首次使用时迁移到工作区范围。迁移可重复检查，删除迁移后的条目不会再次导入旧值。旧设置接口不再允许修改已迁移的 MCP 字段。

## 开发验证

```sh
npm run typecheck
npm run lint
npm test
npx vitest run --project browser src/client/components/McpSettingsPage.browser.test.tsx
npm run verify:managed-mcp-backends
npm run build:sidecar
npm run test:electron:build
```

真实后端验证在临时数据库与配置目录运行，不使用用户的授权账号或全局客户端配置。它分别连接 stdio、无认证 HTTP、带请求头的 HTTP／SSE 和 OAuth fixtures，启动仓库锁定的三个后端，检查上游实际执行结果、模型请求中的工具清单和后端历史中的凭据出口。三个后端各自还会在长调用中修改、禁用及删除服务，验证旧调用完成一次、应用失败可重试、更新后的清单有读取回执。

Codex 只对宿主的受认证入口设置 `default_tools_approval_mode: approve`，由宿主网关继续审批每次上游调用。验证脚本使用生产适配器生成该配置，避免仅凭模型回合结束误判工具已执行。

打包 sidecar 验收使用真实可执行文件启动本地 MCP，完成 OAuth 发现与本机回调，再测试授权后的远程服务。浏览器项目覆盖失败导入的恢复、秘密草稿清理及「已保存／应用失败」并列展示。

服务端存储、解析、管理接口、OAuth、远程传输与调用切换测试位于对应的 `mcp-*`、`managed-mcp-*` 测试文件。客户端测试覆盖参数边界、工作区禁用、范围切换的晚到响应与修订冲突。
