1全局拓扑

Comate 是 Tauri 桌面壳 + Express sidecar + React UI 的三层结构。sidecar 承载全部 agent 运行时编排；新增的后端层（蓝色）把 agent 运行时变成了可插拔的两套实现。

2Agent 后端层（本次新增的核心）

设计要点：共享核心 + 双适配器（KTD-1）。会话核心不感知后端；两个适配器各自把运行时翻译成同一内部消息模型。客户端与渲染层零分支。

agent-backends 注册表（KTD-4）

  • 固定枚举 claude | opencode（方案 B，session-settled）
  • 静态能力声明表：full / degraded / unavailable + reason + evidence 状态位（verified vs declared）
  • 默认值分后端：claude 未声明=full；opencode 未声明=unavailable
  • 可用性 = 二进制解析 + spawn 健康检查（缓存）
  • 应用级默认后端（app-settings.json）+ 不可用回退

会话亲和与锁定（KTD-5/9）

  • sessions.backend：草稿期可选，运行时成功启动后锁定（评审修正：失败不留锁）
  • 锁定后不可改（API 409）；原后端缺失 → 只读 + 提示
  • sessions.backend_session_id：opencode 远端会话 id，用于恢复重连
  • 历史展示与后端无关（opencode 走 REST 历史翻译）
  • 迁移：PRAGMA + ALTER 增量模式，存量默认 claude

claude 适配器

  • BackendDriver 薄封装：现有 SdkClient/query 路径原样包裹
  • 二进制：@anthropic-ai/claude-agent-sdk-{platform}-{arch} optionalDep，四策略解析
  • bot 会话（WeCom/飞书）强制此后端（R14）

opencode 适配器（U4–U7）

  • 每会话一个 serve 子进程：随机 Basic auth、env 净化、Comate 自有 XDG 存储、启动版本校验（锁 1.18.4）
  • 事件映射：SSE → 内部消息模型（text/thinking/tool/todo/idle/error）
  • 审批桥：permission.asked → 核心 canUseTool → once/always/reject
  • 提问桥：question.asked → 问题阶梯 → /question/{id}/reply
  • slash 命令 / 子代理（children 会话翻译）/ fork / 历史加载

5分发形态（U3）

单发布线、双 flavor。两个后端的二进制都经 npm 平台 optionalDependencies 锁版本分发，构建期拷贝进 Tauri resources；变体由 COMATE_BUNDLE_BACKENDS 控制。

形态内容物构建目标场景
default（双后端） claude + opencode 二进制（均为 Mach-O/PE 可执行） npm run release 主流用户；后端自由选择
claude-free（企业） 仅 opencode 二进制；claude 后端按 R3 自动不可见 COMATE_BUNDLE_BACKENDS=opencode npm run release 安全扫描型企业（禁二进制存在）
构建断言按 isFile 校验变体内容（修复：旧目录形残留曾令 existsSync 断言失效）；过期二进制按变体自动清理。版本锁定：opencode 二进制与 @opencode-ai/sdk 钉为同一兼容单元（1.18.4），serve 启动即校验。

7UI 集成

  • 草稿期下拉（仅列可用后端，R3）——与 ProviderSelector 同位同形
  • 锁定后只读徽章（Lock 图标 + 后端名）
  • 原后端不可用 → 红色横幅 + 禁发（R7）
  • bot 会话不渲染（R14）

Settings · Backend（R2）

  • 应用级默认后端选择（双卡 + 可用性指示）
  • 持久化于 app-settings.json
  • 存储后端不可用 → 回退可用后端并提示（KTD-5）

9边界与已知残留（诚实清单）

  • WeCom bot 仅 claude：opencode 的无人值守隔离门未做等价实现（v1 明确排除，后续单评）
  • analytics：opencode 会话暂不计入用量/费用（KTD-10，后续经适配器会话枚举补齐）
  • hooks：双后端均无执行（数据模型半成品），真实执行引擎单独立项
  • 残留风险：MCP Bearer 进入会话 transcript（回环+进程级随机，可接受）；可用性缓存对带外二进制变更不感知（随进程重启刷新）；opencode 原生工具面与 claude 的差异（LSP/WebSearch 等价物）待设备走查确认
  • 验证方式：关键链路均有活验证驱动（surface probes + adapter E2E），能力表带 verified/declared 状态位防自我认证
